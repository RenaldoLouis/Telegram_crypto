# Screener Algorithm Audit — 2026-07-13

Goal: break the "loop of bad logic → bad recommendations," make the system genuinely
regime-adaptive, and lift win rate. Findings below are from the live logs
(237 evaluated trades, 89 eval files, 92 setup files).

---

## A. Diagnosis — the system is stuck in a noise loop AND its core premises are inverted

### A1. The learning loop amplifies noise instead of extracting signal
- **Uncontrolled rule vocabulary.** ~120 distinct free-text `rules_applied` IDs across only
  60 setups. Same idea gets 5 IDs (`ada_short_edge`, `ada_short_edge_revoked`,
  `ada_historical_edge`, `ada_short_historical_edge`, `ada_priority`), risk_off gets 7.
  Every "rule effectiveness" stat is n=1–3 noise.
- **Insights never expire.** Registry: 20 experimental, 0 confirmed, 0 expired. The
  182-batch is 55 trades old (past the 20-trade auto-graduate line) yet still experimental.
  Grading depends on a 2nd Claude call echoing exact insight IDs — it never fires.
- **Contradictions ship to Claude every run.** All in `strategic_rules.md` simultaneously:
  - ADA shorts: #22 "prioritize as Rank-1 anchor" → #29 "suspend, 0/3" → #39 "re-enable cautious-only"
  - BTC bearish anchor: #34 "2/2 wins, high-priority" → #38 "0/4, remove, warning flag"
  - risk_off: #28 "shorts only" → #37 "0/5 shorts, no-trade zone"
- **Auto-graduate is dangerous.** Experimental→confirmed after 20 trades *if not graded*
  would lock in un-validated noise (would have confirmed the contradictory ADA rule).

### A2. Learning objective is WR, not expectancy — so it crowns losers
| Dimension | "Best" by current logic | Reality (net R) |
|---|---|---|
| Setup type | trend_pullback = "BEST TYPE, prioritize" (32% WR) | **−20.7R** (biggest loser, 202/237 trades) |
| Confidence gate | "label high-conf only with 4/4 confluence" | 4/4 is the **WORST** bucket: 18% WR, **−20.4R** |

### A3. Core premises are empirically inverted (nothing in the pipeline reacts)
- **Confluence:** 3/4 = 38% WR **+1.2R** (the only edge). 4/4 = 18% **−20.4R**. 2/4 = 9% −15.9R.
  More agreement = exhausted/late move, not higher probability.
- **Rank:** rank-1 = 26% **−19.7R** (worst). rank-2 = 33% **+2.8R** (only positive). Claude's
  top pick is systematically its worst.
- **Direction:** long 29% **−33.2R** vs short 36% −0.9R. Longs are the entire net loss.
- **Reward leg unreachable:** predicted +1.81R vs actual −0.14R. MFE median 0.79R.
  T2(≥1.5R) hits 11%. (v11.2 T1→0.75R / +0.3R trail already targets this — keep watching.)

### A4. Regime adaptivity is mostly fiction
- Regime stamped only on eval *wrapper*, not per-trade records; 62/259 setup files predate
  the field. Only 56/237 trades attributed. Buckets are 10–16 trades yet generate hard
  directives (no min-sample safeguard, unlike the direction rule which requires 15+).

## B. Remediation plan (tiered)

### TIER 0 — Break the loop (mechanical, git-reversible, low risk)
- **F1. Purge + rebuild `strategic_rules.md` from data with gates.** Drop all 20 `[?]` delta
  insights. Regenerate only rules passing: sample ≥ 20 AND (expectancy-positive to prioritize,
  or clearly-negative to avoid). No WR-only rules.
- **F2. Replace the broken lifecycle.** Grade insights *mechanically* from `by_rule_applied`
  (WR + expectancy of trades citing each canonical rule), not via a Claude echo. Hard-expire on
  negative expectancy or direct contradiction. Remove the auto-graduate-to-confirmed fallback.
  Cap active insights at ~6.
- **F3. Canonical rule taxonomy.** Fixed enum of rule IDs Claude may cite; normalize/reject
  free-text. Kills the 120-ID fragmentation so attribution becomes statistically meaningful.

### TIER 1 — Fix inverted core logic (trading judgment — needs sign-off)
- **F4. Confluence recalibration.** Stop rewarding 4/4; treat it as exhaustion caution. Favor
  3/4 for confidence + pre-filter weighting.
- **F5. Rank de-trust.** Drop conviction ranking or invert it (rank-2 is the edge). At minimum
  stop mapping rank-1 → highest confidence.
- **F6. Long gate / direction bias.** Longs are −33R. Options: much stricter long structural
  gate, or short/neutral bias until longs prove positive expectancy over N trades.
- **F7. Expectancy-based setup-type rules.** Stop calling trend_pullback "BEST TYPE."

### TIER 2 — Real regime adaptivity
- **F8. Fix regime plumbing.** Stamp regime on every eval *result*; backfill from setup files.
- **F9. Min-sample gate on regime rules** (mirror the 15+ direction safeguard).

### D. Screening-side (pre-filter) audit
- **Blind spot fixed**: `interest_score` was never persisted, so the pre-filter's selection quality
  was unmeasurable. Now stamped on each setup + eval result (`bybit_data` → `main` → `weekly_eval`)
  so a future eval can answer "do high-scored candidates actually win?".
- **Open item for the user (not auto-changed)**: the watchlist forces majors into every scan and they
  are chronic losers as *setups* — BTC 3/13 (−5.0R), ETH 2/10 (−6.4R). BTC/ETH are still needed for
  market-context / BTC-trend-guard, so the fix is to keep analyzing them but resist *recommending*
  them (ETH long already blacklisted; confluence + long-cap gates now apply). Consider dropping SOL/
  majors from forced recommendation eligibility once the interest_score data confirms the pattern.

### TIER 3 — Anti-overfit structure
- **F10. Raise delta threshold + require out-of-sample survival** (a rule must hold across the
  *next* batch before "confirmed"). Prevents 15-trade overfits.

Guardrails respected throughout: no execution path, no R:R-floor weakening (1.5:1 stays on T2),
no expanded API perms.

## C. Validation — counterfactual on the 237-trade history

The fixes can't prove a *forward* win rate today, but replaying the new selection gates over the
existing 237 evaluated trades shows they remove the losing slices, not random ones:

| Filter | WR | net R | expectancy | PF |
|---|---|---|---|---|
| Baseline (all triggered) | 30% | −34.0 | −0.144 | 0.75 |
| + long conf≥3 (**shipped**) | 32% | −23.2 | −0.107 | 0.81 |
| + no 4/4 at rank #1 (**shipped**) | 33% | −13.3 | −0.070 | 0.87 |
| + conf≥3 all directions (**shipped**) | 34% | −9.3 | −0.050 | — |
| + drop ALL 4/4 (not shipped — too blunt) | 37% | −2.8 | −0.017 | 0.97 |

**Stopping point (important):** tuning gates further against these same 237 trades would be
overfitting — the exact bad-logic loop the goal warns against. Only gates with large samples and
consistent cross-direction evidence were adopted (conf floor, long structure, no-4/4-rank-1). A
categorical 4/4-long ban was rejected (mechanism fix — fresh-entry requirement — is better than a
blunt ban). Everything past here is decided by FORWARD data via the self-validation marker, not more
in-session tuning.

- The long conf≥3 gate removed exactly the 20 worst longs (15% WR, **−0.544R each**).
- The 4/4 bucket as a whole: 57 trades, 18% WR, −0.36R exp, PF 0.44 — confirmed toxic.
- Shipped gates (long conf≥3 + no-4/4-rank-1) take the book from −34R/PF 0.75 to ≈ −13R/PF 0.87
  on historical data. Dropping 4/4 entirely reaches near-breakeven but is too blunt (kills valid
  trend-following on fresh pullbacks), so 4/4 is handled as "fresh-entry-only, never rank #1"
  rather than a hard ban.

**Note:** these are unrealized counterfactuals on past selections; live forward eval over the next
~20 trades (`eval-scan`) remains the real test. Changes are active for the next local `python main.py`
without a commit (working tree is read at runtime).

### C2. Out-of-sample robustness (forward-generalization proxy)

The gates were derived from all 237 trades, so an in-sample lift could be overfit. Testing whether
they hold on data that best approximates FORWARD conditions:

- **Holdout — most-recent 60 triggered trades**: baseline 32% WR / −0.037R exp → **with gates 36% WR
  / +0.066R exp** (removed slice: 20% WR / −0.344R). The gates produce *positive* expectancy on the
  most-forward-like data — evidence of generalization, not curve-fitting.
- **Consistency by month**: gates IMPROVE expectancy in 3 of 4 months (May −0.10→−0.01, Jun −0.13→+0.01,
  Jul +0.02→**+0.09**); only Apr (oldest, n=31) is marginally worse (−0.52→−0.54). Improvement
  strengthens toward the present.

This is the strongest evidence obtainable in-session. It is a proxy, not live proof — "consistent high
win rate" still requires forward trades, now auto-tracked by the version-marker self-validation.
